# Xi 上下文压缩评测 v1

## 问题

长会话中的模型消息会随着搜索、读取、修改和验证逐步增长。第五里程碑加入了默认
关闭的确定性 Compaction；本实验验证它在同一个可重复代码修复任务上的可观察影响，
并记录是否仍能完成任务和通过唯一测试。

## 变量与条件

- Case：`long_session_compaction`，一个发票汇总遗漏数量的 Python Bug；历史资料文件
  只用于制造足够长的读取上下文，测试和资料路径受保护。
- 模式：`scripted`，固定 ScriptedModel 响应，不调用真实模型或网络。
- 条件：`off`（不传预算）、`budget-1800` 和 `budget-4200`。
- 执行：每个条件由 `benchmarks/compaction.py` 创建独立 output-root，并调用现有
  `benchmarks/run.py`；不复制 Runner 的执行或评分逻辑。

## 指标与判定

每个条件记录 Agent/验证/路径契约、步骤、工具调用、耗时、模型请求次数、每次模型请求
消息的稳定 JSON 字符数总量与最大值，以及 `context_compacted` 的次数、压缩前后字符数
和减少比例。压缩前/后字段是该条件内所有压缩事件的累计值；每个单独快照仍由运行时
按显式预算约束。字符数是可复现的 JSON 字符计数，不是 token 计数。

实验通过标准：关闭条件压缩次数为 0；至少一个预算条件实际压缩且压缩前字符数大于
压缩后字符数；三个条件均完成 Agent 运行、唯一验证、受保护文件和允许改动路径契约；
每次 Runner 调用都必须以 0 退出。失败条件仍保留其结果和产物，不能静默变成成功。

## 解释边界

这是一个单 Case、固定响应的机制验证，不足以推断真实模型的质量、成本或泛化收益。
Live 实验、更多任务和 token 级成本分析不在本里程碑范围内。
